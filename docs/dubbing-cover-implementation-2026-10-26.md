# 电影素材封面实施与发布准备

后续状态：2026-10-28 本文准备的封面功能已部署生产，详见 [正式发布记录](dubbing-cover-release-2026-10-28.md)。下文保留 2026-10-26 的实施和待发布步骤，不作为最新生产状态。

本轮范围：后端管理封面、后台上传/预览、小程序素材列表图片卡片；每条素材一张封面。

## 已实现

- 封面上传读取真实 JPEG/PNG 内容，5 MiB 上限，最大边长 4096、最多 1600 万像素；先检查头部尺寸再解码。UUID 文件名、同目录原子发布，失败清理临时文件。
- 管理员上传/替换携带素材版本；已发布素材先下架。事务失败清理新图，提交后清理旧图；删除素材同时安排封面文件清理。
- 公开清单返回 coverUrl，未发布素材的公开图片为 404；图片响应包含真实 MIME、ETag、缓存重新验证、nosniff。
- 后台封面面板支持预览、元数据和上传/替换；新建未保存、有未保存修改、忙碌或已发布状态禁用上传。
- 小程序封面卡片为 16:9 aspectFill 图片，延迟加载；缺失/失败显示渐变占位，可继续点击进入素材。新封面 URL 恢复图片加载。
- 两张初始封面位于 scripts/dubbing-covers/，来源于各自 Part 01 的 0.5 秒画面，1280×720 JPEG。manifest.json 记录内容哈希、尺寸和字节数。

- 图片存储及服务生命周期测试先确认缺少实现再实现；URL 适配回归测试先失败再通过。后台及真实 React DOM 卡片测试验证最终行为。

- 数据库字段仍允许空值，发布新素材要求封面；旧清单缺失封面字段时小程序继续显示占位，兼容升级窗口。

验证边界：微信开发者工具/真机实际图片显示与缓存、生产 Nginx 配置和发布流程未执行。隔离数据库最初在中文目录启动退出，改用本次有写权限的英文临时目录后验证成功；未读取或修改生产数据库。临时测试实例已关闭。

1. 备份生产数据库、/opt/yue/dubbing-videos、后端制品、管理端和小程序源码，新增封面目录也纳入一致备份。
2. 显式执行 scripts/dubbing-cover-migration.sql，可重复执行；不依赖 Hibernate 自动改表。
3. 创建应用可读写的 /opt/yue/dubbing-covers，设置 ADMIN_DUBBING_COVER_DIR 指向该目录。
4. 以应用服务账号执行 `python scripts/generate-dubbing-covers.py --target-dir /opt/yue/dubbing-covers`，校验随仓库图片哈希并导入；重复导入不会覆盖不同内容。导入文件初始权限为 0600；若由管理员导入，需先将文件所有者设为应用账号并确认可读，再切换后端。
5. 导入成功后执行 scripts/dubbing-cover-seed.sql；只回填 cover_file_name 为空的两条已知素材，保留运营已有封面。重复执行不增加版本。
6. 验证两条素材封面元数据、文件哈希和实际可读性，再部署新后端和管理端。Nginx 为 `/api/admin/dubbing-materials/[0-9]+/cover` 配置至少 `client_max_body_size 6m`（5 MiB 文件加 multipart 开销），与既有 `/api/` 一样代理到后端；使用 `nginx -t` 验证后重载。检查图片 200/304、未发布图片 404、管理员 401/403、旧视频 Range 播放及邮箱/ASR 门禁。
7. 小程序重新构建，在微信开发者工具/真机检查图片显示、失败占位和点击跳转，再单独上传审核。

重新生成初始封面：`python scripts/generate-dubbing-covers.py --source-dir <approved-clips> --target-dir <new-output-dir>`；源 MP4 哈希必须匹配审核清单。不同 FFmpeg 版本可能产生不同 JPEG 字节，重新生成不会覆盖已存在的不同图片；发布导入以 checked-in manifest 为准。

回滚应用时保留封面字段和文件；不要仅回滚数据库或单独清理封面目录。生产迁移、部署和微信审核需后续发布授权。
