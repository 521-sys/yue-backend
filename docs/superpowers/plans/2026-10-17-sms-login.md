# 短信登录与登录界面改造实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为网页“我的”入口提供参考图风格的密码/短信登录界面，并以腾讯云短信、一次性验证码、自动注册和现有 JWT/学习同步完成真实短信登录。

**Architecture:** 后端用独立短信领域包隔离验证码存储、发送策略和腾讯云适配器，MySQL 负责一次性消费与限流状态；REST 层只做输入、客户端 IP 和错误映射。前端用可复用认证流程组件同时服务“我的”整页和既有功能弹层，API/store 继续复用现有登录后同步路径。

**Tech Stack:** Java 21、Spring Boot 3.2.5、Spring Data JPA、MySQL 8、腾讯云 Java SMS SDK、React 19、TypeScript、Vitest、Testing Library、Tailwind CSS 4。

**Spec:** `docs/superpowers/specs/2026-10-17-sms-login-design.md`

## Global Constraints

- 只支持中国大陆 11 位手机号；短信验证码为 6 位数字、默认 5 分钟有效、最多错误 5 次。
- 默认限流为同手机号 60 秒 1 次、每日 10 次，同 IP 每日 30 次；后端是限流权威。
- 验证码及完整手机号不得写入日志；验证码仅以 HMAC-SHA-256 保存，密钥仅来自 `SMS_CODE_PEPPER`。
- 腾讯云短信使用独立最小权限凭据；生产没有固定验证码、回显验证码或日志验证码的测试后门。
- 短信未配置或关闭时只影响短信接口；账号密码、手机号密码和微信小程序登录必须保持可用。
- 不实现“忘记密码”、国际短信、Redis 或微信登录改造；无协议页面时不增加无功能链接。
- `yue-frontend` 的现有未提交语音改动和 `dist.tgz` 必须保留且不得纳入本功能提交。
- 两个仓库分别提交；根目录不是 Git 仓库，`项目现状总结.md` 只在最终验证后更新且不伪称已提交。

## Review Focus

- 非法手机号、包含空格/全角字符或超过 6 位的验证码必须在进入业务逻辑前返回 `400`，不能被隐式截断为另一个账号。
- 同一手机号并发发送和同一验证码并发提交时，分别只能产生一次供应商发送和一次成功登录。
- 供应商请求发生超时、结果未知时不得立即允许重复发送；保留短时预约并向用户返回可重试提示。
- 只有来自配置中受信任代理地址的 `X-Forwarded-For` 才能用于 IP 限流，公网客户端伪造的请求头必须被忽略。
- 短信自动注册用户的随机密码占位值不能通过账号或手机号密码登录命中，也不能改变既有用户的密码哈希。
