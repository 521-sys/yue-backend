# 网页短信登录与登录界面改造设计

日期：2026-10-17  
状态：待用户审阅  
范围：`yue-frontend` 网页用户端、`yue-backend` 认证接口与生产配置

## 1. 背景与目标

当前网页在未登录状态下仍展示“我的”页中的每日学习目标、重置学习进度等设置，真正的登录表单则位于底部抽屉。现有表单还使用“账号/手机号”和“登录/注册”两层切换，信息层级与登录任务不匹配。

本次改造目标：

1. 未登录用户进入“我的”时直接看到清晰的登录界面，不再看到登录后才有意义的个人设置。
2. 登录界面参考用户提供的视觉：顶部使用“密码登录 / 短信登录”标签，输入区域简洁，主操作明确。
3. 保留现有用户名、手机号密码登录和注册能力，同时增加真正的国内手机号短信验证码登录。
4. 短信验证码验证成功后，已有手机号直接登录；新手机号自动创建账号并登录。
5. 沿用现有 JWT 和学习状态同步流程，不改变其他三个主入口及微信小程序登录。

## 2. 非目标

- 本期不实现找回或重置密码，因此不展示无功能的“忘记密码”链接。
- 本期不新增邮箱登录、第三方网页登录或国际/港澳台手机号短信。
- 本期不改微信小程序的 `wx.login` 登录链路。
- 本期不新增 Redis；验证码与限流数据使用现有 MySQL。
- 用户协议和隐私政策没有可访问页面前，不增加伪链接；上线短信登录前应另行确认现有站点合规文本是否满足收集手机号的要求。

## 3. 用户体验

### 3.1 未登录状态

“我的”页保留底部四项主导航，上方主体改为登录面板：

- 标题说明登录后可同步学习进度。
- 标签一：`密码登录`。
  - 第一项为“账号或手机号”。前端根据中国大陆手机号格式选择现有 `/api/auth/phone/login`，否则选择 `/api/auth/login`。
  - 第二项为密码，提供显示/隐藏按钮。
  - 主按钮为“登录”。
  - 底部“快速注册”进入与新样式一致的注册面板，继续支持账号注册和手机号加密码注册。
- 标签二：`短信登录`。
  - 第一项为 11 位手机号。
  - 第二项为验证码，右侧为“获取验证码”；发送成功后进入 60 秒倒计时。
  - 主按钮为“登录”。手机号不存在时，验证码验证成功即自动注册。
- 错误显示在对应表单内，切换标签时清除不相关错误，但保留已输入手机号。

页面需支持键盘提交、输入标签、焦点样式、加载禁用和屏幕阅读器可识别的错误提示。样式参考图的布局和轻量层级，但继续使用现有蓝色品牌色，不复制参考产品的黄色品牌按钮。

### 3.2 已登录状态

继续展示现有头像、昵称、编辑资料、退出登录、每日学习目标和重置进度。此次只调整未登录分支；登录成功后通过现有认证状态事件切换页面，并执行现有学习数据同步。

## 4. 前端设计

认证界面拆为独立、可测试的组件，`ProfileScreen` 只负责根据 `isLoggedin()` 选择未登录界面或已登录个人页：

- `LoginPanel`：密码/短信标签、字段状态和提交行为。
- `RegisterPanel`：承接现有账号及手机号密码注册，不与登录标签形成双层切换。
- `AuthSheet`：不再作为未登录“我的”页的主入口；如其他代码仍依赖则保留为兼容包装，否则在确认无引用后移除。

`src/lib/api.ts` 新增：

- `sendSmsLoginCode(phone)`
- `smsLogin(phone, code)`

`src/lib/store.ts` 新增 `smsLoginAndSync`，成功后与现有登录完全相同地保存 token、用户信息并同步学习状态。验证码倒计时只用于改善体验，后端仍是发送频率的权威判断；刷新页面不能绕过后端限流。

## 5. 后端接口

### 5.1 发送验证码

`POST /api/auth/sms/code`

请求：

```json
{ "phone": "13812345678" }
```

成功响应使用 `202 Accepted`：

```json
{ "accepted": true, "retryAfterSeconds": 60 }
```

接口不返回验证码，也不返回手机号是否已注册。短信功能未配置或未启用时返回明确的服务不可用错误；生产环境不存在返回固定验证码或把验证码写入日志的后门。

### 5.2 验证码登录

`POST /api/auth/sms/login`

请求：

```json
{ "phone": "13812345678", "code": "123456" }
```

成功响应沿用现有 `AuthResponse`。验证成功后：

- 已有该手机号：签发现有 JWT。
- 没有该手机号：在事务中自动生成唯一用户名和默认昵称，写入手机号后签发 JWT。
- 新建短信用户写入随机、不可登录的密码哈希占位值，避免产生默认密码；以后若实现密码设置或找回，必须先重新验证手机号。

验证码错误、过期、已使用或尝试次数耗尽统一返回“验证码无效或已过期”，避免泄露内部状态。

## 6. 验证码存储与并发

新增 `sms_login_codes` 表，生产迁移脚本显式创建，生产继续使用 Hibernate `validate`：

- `id`
- `phone`
- `code_hash`
- `request_ip_hash`
- `created_at`
- `expires_at`
- `consumed_at`
- `failed_attempts`
- `status`（`PENDING`、`SENT`、`CONSUMED`、`FAILED`）
- `provider_request_id`

验证码为密码学安全随机生成的 6 位数字。数据库只保存使用服务端高强度随机 pepper 计算的 HMAC-SHA-256，不保存明文；请求 IP 同样只保存不可逆哈希。验证码默认 5 分钟有效，同一手机号新验证码发送成功后使旧验证码失效。

发送前先以原子方式写入短时 `PENDING` 预约，阻止同一手机号的并发请求同时调用供应商。供应商接受后改为 `SENT` 并开始 60 秒冷却；供应商拒绝或调用异常时改为 `FAILED`，不占用正常冷却。超时的 `PENDING` 记录可以安全释放。

登录校验通过与标记 `consumed_at` 必须在同一事务内完成，并通过行锁或等效条件更新保证同一验证码只能消费一次。自动注册需依靠用户表手机号唯一约束处理并发；发生并发插入时重新读取已存在用户，而不是创建重复账号。

过期记录可在登录和发送时做小批量清理，并增加每日定时清理，默认仅保留安全审计所需的短期窗口，不长期保存验证码记录。

## 7. 防刷与安全边界

默认限制：

- 同一手机号 60 秒内最多发送 1 次。
- 同一手机号每天最多发送 10 次。
- 同一 IP 每天最多发送 30 次。
- 每个验证码最多允许 5 次错误尝试。
- 发送接口对外使用通用成功文案；服务端记录供应商请求 ID、结果码和脱敏手机号，不记录验证码及完整手机号。

限流阈值通过配置项提供，但生产环境必须有保守默认值。短信供应商明确接受发送请求后才开始冷却；供应商调用失败不得让一个用户永远收不到的验证码占用正常冷却期。用于限流的客户端 IP 只接受受信任反向代理写入的转发头，不能直接信任公网客户端自报的 `X-Forwarded-For`。

API 密钥不发送到浏览器、不提交 Git。短信使用专用、最小权限的腾讯云子账号密钥，与现有语音识别密钥分离。

## 8. 腾讯云适配与配置

后端定义短信发送端口，腾讯云实现负责调用官方 Java SDK。业务服务只依赖该端口，测试使用内存假实现，不调用真实短信，也不消耗额度。

生产配置项：

- `SMS_ENABLED`
- `SMS_TENCENT_SECRET_ID`
- `SMS_TENCENT_SECRET_KEY`
- `SMS_TENCENT_SDK_APP_ID`
- `SMS_TENCENT_SIGN_NAME`
- `SMS_TENCENT_TEMPLATE_ID`
- `SMS_CODE_PEPPER`
- 可选的有效期和限流阈值

只有开关开启且必需配置齐全时才允许发送。应用启动时校验配置；缺项时短信接口不可用，但密码登录、微信登录及其他功能继续工作。

用户需在腾讯云完成短信服务开通、认证、国内短信签名和验证码模板审核，并通过服务器环境变量提供配置。任何密钥均不要求在聊天或文档中明文传递。

## 9. 错误处理与可观测性

- 参数格式错误返回 `400`。
- 验证码无效或过期返回 `400`，使用统一提示。
- 触发限流返回 `429`，响应包含可安全公开的重试秒数。
- 短信未配置或供应商暂时不可用返回 `503`。
- 供应商错误映射为站内稳定错误，不把腾讯云内部信息或凭据返回前端。

记录发送尝试数量、成功/失败数量、限流数量和登录成功数量；日志只包含脱敏标识。生产验证需同时检查腾讯云控制台下发状态和本站日志，不以 API 接收成功等同于手机送达。

## 10. 测试策略

按测试先行实现：

### 后端

- 发送成功、配置未启用、供应商失败。
- 手机号与 IP 限流、60 秒冷却。
- 正确、错误、过期、重复消费和错误次数耗尽。
- 已有用户登录与新手机号自动注册。
- 同一验证码并发消费和同一手机号并发注册。
- Controller 参数校验、状态码和错误响应。
- MySQL 迁移专项验证。

### 前端

- 未登录只显示登录界面，不显示学习设置。
- 密码登录能按输入选择账号或手机号接口。
- 短信发送、倒计时、重复点击禁用、错误提示。
- 短信登录成功后保存认证状态并同步学习数据。
- 登录后恢复现有个人页，退出后返回登录界面。
- 注册入口和现有注册能力不回归。

最后运行两个仓库的相关测试、完整测试和生产构建。真实短信只在腾讯云配置完成后做一次受控验收，使用指定测试手机号，避免批量消耗和向无关人员发送短信。

## 11. 发布与回滚

发布顺序：

1. 备份数据库并执行幂等迁移脚本。
2. 部署短信功能默认关闭的新后端，验证密码与微信登录无回归。
3. 配置腾讯云参数和额度/频率告警，开启短信功能并做一次真实验收。
4. 部署新网页登录界面并完成移动端浏览器验收。
5. 更新根目录 `项目现状总结.md`、前后端开发记录和部署验证记录。

紧急回滚时先关闭 `SMS_ENABLED`，密码登录仍可使用；必要时回滚网页和后端包。新增验证码表可以保留，不阻碍旧版本运行，不在紧急回滚中删除数据结构。

## 12. 验收标准

- 未登录“我的”页不再出现每日目标或重置进度。
- 两种登录标签布局与参考图相似、符合现有品牌色，并在常见手机宽度正常显示。
- 密码登录、现有注册和微信小程序登录保持可用。
- 国内手机号能收到验证码，正确验证码可登录，新手机号可自动注册。
- 验证码不可重复使用，过期和限流按设计生效，日志与响应不泄露验证码、完整手机号或密钥。
- 自动化测试、前后端生产构建及一次受控真实短信验收通过。
