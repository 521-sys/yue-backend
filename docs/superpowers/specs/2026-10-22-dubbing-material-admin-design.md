# 电影配音素材后台管理设计

日期：2026-10-22  
状态：待用户审阅  
范围：`yue-backend`、`yue-admin`、`yue-frontend`、生产数据库与电影片段存储

## 1. 背景与目标

用户网页的“电影模仿”已经支持内置素材详情、Part 切换、逐句录音、整片预览和浏览器草稿恢复，但当前两套素材仍由前端 TypeScript 配置和静态 MP4 文件提供。新增、修改或下架素材都必须重新构建并部署用户网页，现有运营后台不能管理这些内容。

本次改造目标：

1. 后台成为电影配音素材的唯一管理入口和数据权威。
2. 管理员可以维护电影资料、多个 Part、Part 视频、逐句粤语台词、来源与许可，并执行排序、发布、下架和删除。
3. 用户网页只读取公开接口中的已发布素材，不再依赖编译进前端的素材清单。
4. 现有 `PENDATANG：搬入新家` 和 `正确洗手（粤语）` 及六段视频迁入后台，保持线上内容连续。
5. 保留现有素材、Part 和台词的稳定编码，使当前浏览器已经保存的内置素材草稿能够继续恢复。

## 2. 已确认范围与非目标

第一版由管理员上传已经裁剪好的 Part 视频，不上传整部电影，也不在服务器上做在线裁剪或转码。

本期不实现：

- 整片上传、时间轴裁剪、自动转码或自动拆 Part。
- 自动生成台词；管理员录入或粘贴已经核对的粤语台词和时间点。
- 独立封面上传、简介、排行榜、点赞、礼物、完成用户或其他社交功能。
- 用户配音作品的云端保存或 MP4 导出。
- 视频对象存储/CDN；第一版继续使用现有单台服务器的本地持久化目录。
- 小程序电影配音入口。

## 3. 方案选择

采用规范化数据库方案：电影、Part 和台词分别持久化，Part 直接拥有一个受管视频文件。相比单表 JSON，该方案能对稳定编码、顺序、时间范围和发布条件建立清晰约束；相比后台写静态前端文件，该方案不依赖重新构建用户网页，并能复用现有管理员鉴权、审计和乐观锁流程。

生产视频存放在 `/opt/yue/dubbing-videos`。数据库保存文件元数据，不保存视频二进制。目录与数据库属于同一备份和恢复单元。

## 4. 数据模型

### 4.1 `dubbing_materials`

- `id`：数据库主键。
- `code`：对外稳定素材编码，唯一且创建后不可修改；沿用当前前端 `materialId`。
- `title`：素材标题。
- `difficulty`：显示难度，例如 `B1`、`B2`。
- `tags_json`：标签字符串数组的 JSON 表示；最多 10 项，每项最多 30 字。
- `source_label`、`source_url`：作者/来源显示文字和原始素材链接。
- `license_label`、`license_url`：许可显示文字和许可链接。
- `status`：`DRAFT`、`PUBLISHED`、`OFFLINE`。
- `sort_order`：越小越靠前。
- `version`：JPA 乐观锁版本。
- `created_at`、`updated_at`。

来源和许可链接只接受 `http` 或 `https` 绝对地址；后端不主动抓取这些地址，避免把管理字段变成服务端请求入口。数据库保存管理员已经完成的版权核验结果，但系统本身不自动判断许可有效性。

### 4.2 `dubbing_parts`

- `id`：数据库主键。
- `material_id`：所属素材外键。
- `code`：素材内唯一、对外稳定的 Part 编码；沿用当前前端 `partId`。
- `label`：例如 `Part 01`。
- `title`：Part 标题。
- `sort_order`。
- `video_key`：不可猜测的公开资源标识。
- `original_name`、`file_name`、`content_type`、`size_bytes`。
- `duration_ms`、`video_codec`、`audio_codec`：由 FFprobe 读取，不接受浏览器自报。
- `video_version`：每次替换视频递增，用于公开 URL 的缓存失效。
- `version`、`created_at`、`updated_at`。

新建 Part 可以暂时没有视频，但没有有效视频的 Part 不能随素材发布。删除 Part 会同时删除其台词；已发布素材中的 Part 只能在素材下架后删除或替换视频，防止用户使用过程中内容突然变化。

### 4.3 `dubbing_cues`

- `id`：数据库主键。
- `part_id`：所属 Part 外键。
- `code`：Part 内唯一、对外稳定的台词编码；沿用当前前端 cue `id`。
- `sequence_no`：显示和录制顺序。
- `start_ms`、`end_ms`：相对当前 Part 视频的毫秒时间。
- `text`：粤语台词。

每句必须满足 `0 <= start_ms < end_ms <= duration_ms`，文字不能为空。同一 Part 最多 200 句；允许原字幕本身存在时间重叠，不强制把相邻台词改写成不重叠区间。

## 5. 视频上传、存储与读取

管理员为每个 Part 单独上传 MP4：

- 最大 200 MiB，最长 5 分钟。
- 容器必须是 MP4，视频必须为 H.264，音频必须为 AAC。
- 后端先流式写入同目录临时文件，再检查文件签名并运行 FFprobe；扩展名或浏览器 `Content-Type` 不能作为有效性依据。
- 校验成功后使用随机文件名原子移入受管目录；失败时删除临时文件。
- 替换视频先保存并验证新文件，数据库事务成功后才删除旧文件；事务失败则删除新文件并保留旧文件。
- 替换视频后重新校验所有台词。若任何 `end_ms` 超过新时长，拒绝替换并保留旧视频。

视频响应采用流式读取并支持标准 HTTP Range，不能像现有小音频接口一样将整个文件读入内存。公开视频接口只允许读取已发布素材中的 Part；管理员预览接口在管理员鉴权后可以读取草稿或下架素材。响应包含正确的 `Content-Type`、`Content-Length`、`Accept-Ranges`、`ETag` 或等价版本缓存信息。

## 6. 管理后台体验

侧栏新增“电影素材”独立菜单。

列表页支持：

- 按标题或稳定编码搜索。
- 按发布状态筛选。
- 展示难度、Part 数、状态、更新时间和排序。
- 新建、编辑、发布、下架；删除从编辑页执行。

编辑页分为三个区域：

1. 素材资料：标题、难度、标签、排序、作者/来源说明、来源链接、许可名称、许可链接。
2. Part 管理：增加、删除、排序 Part，编辑稳定编码、标签和标题，上传/替换视频并预览。
3. 台词编辑：按行编辑稳定编码、开始毫秒、结束毫秒和粤语文字，并可增删、排序。

沿用现有未保存离开提醒、加载/错误提示和乐观锁冲突处理。已发布素材允许修改普通文字和台词，保存后立即影响用户端，页面必须显示明确警告；已发布时禁止替换视频、删除 Part 或删除素材。发布、下架、创建、编辑、上传、替换和删除都写管理员审计日志。

## 7. 后端接口

### 7.1 管理员接口

统一位于 `/api/admin/dubbing-materials`：

- `GET /api/admin/dubbing-materials`：搜索、状态筛选和分页。
- `GET /api/admin/dubbing-materials/{id}`：返回素材、Part、台词和视频元数据。
- `POST /api/admin/dubbing-materials`：创建草稿。
- `PUT /api/admin/dubbing-materials/{id}`：保存素材、Part 顺序和台词；要求素材版本。
- `PUT /api/admin/dubbing-materials/{id}/status`：发布或下架；要求素材版本。
- `DELETE /api/admin/dubbing-materials/{id}`：仅删除非发布素材；要求版本。
- `POST /api/admin/dubbing-materials/{id}/parts`：创建 Part。
- `POST /api/admin/dubbing-materials/{id}/parts/{partId}/video`：上传视频。
- `PUT /api/admin/dubbing-materials/{id}/parts/{partId}/video`：替换视频，仅限非发布素材。
- `GET /api/admin/dubbing-materials/{id}/parts/{partId}/video`：管理员视频预览，支持 Range。

所有管理员接口继续受 `ROLE_ADMIN` 保护。请求校验返回稳定中文错误；资源不存在返回 `404`，版本冲突返回 `409`，上传过大返回 `413`，媒体格式不支持返回 `415`。

### 7.2 公开接口

- `GET /api/public/dubbing-materials`：返回所有已发布素材及其 Part、台词，按素材和 Part 排序；不分页。
- `GET /api/public/dubbing-materials/{code}`：按稳定编码返回一条已发布素材。
- `GET /api/public/dubbing-materials/{materialCode}/parts/{partCode}/video?v={videoVersion}`：流式返回已发布视频并支持 Range。

公开 DTO 不暴露数据库文件名、磁盘路径、内部主键或草稿数据。列表数据量在第一版保持为小型策划内容；未来数量显著增加时再增加分页或清单版本缓存，本期不提前设计。

## 8. 发布规则、并发和删除

素材发布前必须满足：

- 素材标题、难度、来源文字、来源链接、许可文字和许可链接完整。
- 至少有一个 Part。
- 每个 Part 的稳定编码、标签、标题、有效视频和至少一句台词完整。
- 所有台词时间均在对应视频真实时长内。
- 素材、Part 和台词稳定编码在各自范围内唯一。

新素材默认 `DRAFT`。`PUBLISHED` 可以转为 `OFFLINE`，下架后不再出现在任何公开元数据或视频接口。已发布素材不能直接删除；必须先下架。删除素材时在同一数据库事务中删除 Part 和台词，事务提交后清理对应视频文件。

素材更新与状态变更使用素材级乐观锁。视频替换和 Part 删除在事务内锁定所属素材，避免并发保存产生文件引用错配。后台收到 `409` 后要求重新加载，不自动覆盖其他管理员的更新。

## 9. 用户网页数据流与兼容

用户进入“电影模仿”时请求公开素材列表：

- 加载中显示明确状态。
- 成功但列表为空时显示暂无已发布素材，并保留“导入我的视频”。
- 请求失败时显示错误和“重新加载”，同时保留“导入我的视频”。
- 不回退编译时静态素材清单，避免后台下架后用户端仍展示旧素材。

公开 DTO 在用户端映射为当前 `DubbingMaterial`、`DubbingMaterialPart` 和 `DubbingCue` 结构，现有录音和预览工作区不重新实现。视频地址使用公开接口和 `videoVersion`。

浏览器草稿继续保存 `materialId`、`partId` 和 cue 编码。迁移保持现有编码后，两套线上素材的已有草稿可恢复。若素材后来下架、删除或接口暂时不可用，草稿不被覆盖，页面提示“上次使用的内置素材当前不可用，请重新选择素材”；用户自行上传的视频草稿不受影响。

## 10. 现有素材迁移

迁移脚本和导入工具必须可重复演练且不会重复创建数据：

1. 创建三张表、索引、唯一约束和外键。
2. 以稳定编码插入或核对两个素材：`pendatang-arrival`、`sfdph-wash-hands-cantonese`。
3. 保留六个 Part 编码和现有 25 个 cue 编码、文本、顺序及时间点。
4. 将六段现有 MP4 复制到受管视频目录，写入随机存储文件名、真实大小、时长、编解码和 SHA-256 核对结果。
5. `PENDATANG` 排在前，“正确洗手”排在后；两条迁移完成后保持 `PUBLISHED`。
6. 导入失败时不切换新后端和用户网页；现有静态站继续提供素材。

迁移不从互联网重新下载原片。导入只使用工作区已经核验并上线的六段成品。部署完成后，前端发布包不再携带这些视频；受管目录和数据库备份确认可恢复后，旧静态站备份继续按发布备份策略保留。

## 11. 安全、资源与运维边界

- 视频上传继续经过管理员 JWT 权限检查，并扩展当前上传过滤器的路径识别、200 MiB 限制和单任务并发保护。
- 文件名由服务端生成；任何磁盘访问都在规范化后的受管目录内，不能接受客户端路径。
- FFprobe 设定超时并限制输出读取；本期不执行 FFmpeg 转码。
- 生产以 Hibernate `validate` 启动，必须先显式执行幂等 SQL 迁移。
- `/opt/yue/dubbing-videos` 权限只允许应用服务账号和备份流程访问；公网只能经受控视频接口读取。
- 数据库备份、视频目录和应用制品构成一次协调备份；回滚不得只恢复数据库或只恢复文件。
- 日志和审计记录素材/Part 标识、动作和错误，不记录视频内容或服务器绝对路径。

## 12. 错误处理

- 保存表单失败时后台保留当前输入并显示后端稳定错误。
- 上传失败不创建有效视频引用；重复上传需由管理员再次触发，不自动重试大文件。
- 数据库提交失败清理新文件，保留旧文件；旧文件删除失败记录告警并留给受控孤儿清理，不让已成功事务回滚成无引用状态。
- 公开列表只要一个数据库记录损坏就不应静默返回半份素材；服务记录错误并返回失败，避免用户录音时引用不完整台词。
- Range 不合法返回 `416`；未发布或不存在的视频统一返回 `404`，不泄露草稿是否存在。

## 13. 测试策略

按测试先行实现。

### 后端

- 实体默认状态、稳定编码唯一约束和关系删除。
- 创建、编辑、排序、发布、下架、删除和审计流程。
- 缺视频、无台词、时间越界、许可缺失和编码重复时拒绝发布。
- 管理员权限、公开接口只读已发布素材、草稿视频不泄露。
- MP4/H.264/AAC 成功；伪扩展名、错误编解码、过大、超时和超过 5 分钟失败。
- 视频替换成功、台词超出新时长时拒绝、事务失败清理新文件并保留旧文件。
- 完整与分段 Range 响应、无效 Range `416`，并证明视频不是整文件读入内存的接口契约。
- 乐观锁冲突和并发视频替换。
- MySQL 迁移重复执行、外键/索引核对和两套现有素材导入一致性。

### 管理后台

- 电影素材菜单、列表搜索/筛选、空态和错误重试。
- 新建与编辑资料、标签、Part 和台词。
- 上传/替换视频状态、格式错误、版本冲突和未保存离开提示。
- 发布前错误展示、发布/下架、已发布时禁止危险操作。
- 视频预览和台词时间编辑的可访问标签。

### 用户网页

- 加载公开素材并按后台顺序展示。
- 接口失败重试、空列表和“导入我的视频”始终可用。
- 已发布素材的 Part、台词和带版本视频地址进入现有工作区。
- 不回退静态素材；下架后不再展示。
- 现有稳定编码草稿恢复、素材不可用提示和用户自有视频恢复不回归。

三个仓库分别运行相关测试、完整测试和生产构建。媒体校验使用小型本地夹具，不在自动化测试中访问互联网。

## 14. 部署与回滚

固定发布顺序：

1. 只读预检生产数据库、服务、Nginx、磁盘和现有六段视频。
2. 创建包含数据库、当前用户站、管理站、后端、配置和视频目录的协调备份。
3. 在隔离数据库和临时视频目录重复演练迁移与导入，并核对数量、编码、哈希和时长。
4. 生产执行数据库迁移和六段视频导入。
5. 部署后端，验证管理员接口、公开接口、Range 和既有鉴权门禁。
6. 部署管理后台并用临时草稿完成新建、上传、编辑、发布、下架和删除验收；清理测试数据。
7. 部署用户网页，验证两套现有素材、Part、台词、录音入口和浏览器草稿恢复。
8. 更新项目现状和开发/发布记录。

任何阶段失败都停止后续切换。若新用户网页尚未部署，旧静态站仍可独立工作；若已完成全量切换，则按协调备份同时恢复数据库、视频目录、后端和两个前端，不能混用新旧数据结构。新增表可以在仅回滚应用时保留，但若恢复了旧数据库快照，必须同时恢复匹配的视频目录。

## 15. 验收标准

- 管理员能在后台完成一条素材从草稿、多个 Part、视频和台词编辑到发布、下架和删除的完整流程。
- 未发布内容和视频不能通过公开接口读取；已发布内容无需用户登录即可在“电影模仿”中使用。
- 六段现有视频、两个素材、六个 Part 和 25 句台词迁移后内容与顺序一致，现有稳定编码不变。
- 用户网页不再打包电影素材清单或六段视频；后台下架后刷新用户网页即不再显示该素材。
- 视频可播放、拖动，Range 请求正确，上传和播放不会把 200 MiB 文件整体载入 JVM 内存。
- 版本冲突不会静默覆盖其他管理员修改，失败上传或数据库回滚不会误删旧视频。
- 三个仓库完整测试和生产构建通过，迁移演练、协调备份、生产接口及浏览器验收均有新记录。
